你是不是也遇到过

本地开发/自托管服务越多，这些琐事越烦人

端口根本记不住

58628 是什么？15173 又是什么？浏览器历史里一排 127.0.0.1:xxxx，每次都要翻半天。

手改 hosts 太黑盒

要管理员权限、改完忘了清、残留条目越攒越多，哪行是哪来的完全不知道。

换了域名就 403 / WebSocket 401

很多本地服务开了 Host 校验 / DNS-rebinding 防护，用自定义域名访问直接被拒，WebSocket 握手失败。

地址栏永远"不安全"

http 明文地址被浏览器打上"不安全"标记，看着难受，某些 API（剪贴板等）在非安全上下文还受限。

重启电脑全失效

临时起的反向代理、临时改的 hosts，重启之后又要重新折腾一遍。

自己搭反代嫌麻烦

Caddy/nginx 能干这事，但要写配置、管进程、处理证书——为了一个域名映射，值吗？

LocalMap 怎么解决

一个常驻引擎 + 一个桌面 GUI，全部可视化，不再是黑盒

浏览器
myapp.local → LocalMap 引擎
127.0.0.1:80 / :443 → 目标服务
127.0.0.1:58628

映射表 GUI 管理

域名 ↔ 端口一表看清，增删改即时生效；桌面 app 一键"打开/复制地址"。

hosts 受管区块，可审计

只写 # >>> LOCALMAP <<< 标记之间的区块，绝不动你其它条目；区块内容随时可查。

自动绕过 Host/Origin 校验

转发时把 Host 改写为目标地址、同源 Origin 改写为目标源，WebSocket/SSE 原生透传，403/401 消失。

一键本地 HTTPS

自签 CA 装入系统信任存储（无弹窗），按域名自动签发证书，http 自动 308 跳转 https，"不安全"标识消失。

开机自启，重启不丢

计划任务以 SYSTEM 身份常驻引擎（无窗口），重启后域名、HTTPS 全部自动恢复。

完整闭环，随时反悔

"关闭并删除证书"一键回滚：停 443、删系统 CA、删证书文件。计划任务也可一键删除。

为什么可以放心用

本地工具的底线：不联网、不越权、可审计、可回滚

  • 只监听 127.0.0.1 —— 代理和控制 API 都不绑 LAN/公网地址，局域网其它设备摸不到。
  • 变更 API 需 token 鉴权 —— 自定义请求头鉴权，天然免疫浏览器表单 CSRF。
  • 控制 API 校验 Host 头 —— 只响应 127.0.0.1 / localhost / localmap.test，拦截 DNS-rebinding 窃取 token。
  • 不削弱目标服务的防护 —— 只有同源 Origin 才改写，第三方站点的跨域请求原样转发，仍会被目标服务拒绝。
  • hosts 改动限定在受管区块 —— 只增删自己标记之间的行，其它内容一个字不动。
  • 本地 CA 完全受你控制 —— 证书和私钥只存在本机 data/ 目录，一键即可从系统信任存储彻底删除。
  • 零依赖、全开源（MIT） —— 引擎是单文件 Go 程序（仅标准库），桌面壳是 Tauri，每一行都能审。

常见问题

需要管理员权限吗？
桌面 app 本身不需要。引擎需要（绑定 80/443 端口、写 hosts），所以推荐在 app 里一键注册计划任务，让引擎以 SYSTEM 身份常驻，之后日常使用无需任何提权。
Firefox 能用 https 吗？
Firefox 使用独立证书库，不信任系统根存储。需要在 设置 → 隐私与安全 → 证书 → 导入 中手动信任 data/ca.crt。Chrome/Edge 无需任何操作。
80 或 443 端口被占了怎么办？
引擎启动失败时会在日志里说明。常见占用方是 IIS、Skype、Docker 或其它反代，停掉它们或改端口后重试即可。
和 Caddy / nginx 有什么区别？
它们是通用反代，LocalMap 是专门为"本机端口 ↔ 域名"场景做的：hosts 自动同步、Host/Origin 自动改写、本地 CA 自动签发与信任、桌面 GUI、开机自启——全部开箱即用，不用写一行配置。
换域名后目标服务要重新登录？
是的。浏览器的 localStorage 按域名隔离，目标服务（如带 token 的本地 Web UI）第一次用新域名访问时，需要重新走一次它自己的登录/引导流程。http 换 https 同理。
域名会影响公网吗？
不会。hosts 条目只在本机生效，域名不需要真实注册。建议用 .local / .test 这类保留后缀，避免和真实域名冲突。
